fix(probe): ARC / ObjC 两处硬错误 + 新增本地静态闸门

CI 报错：
  BiliProbe.m:194:10 error: bad receiver type 'SEL'
  BiliProbe.m:195:16 error: cast of 'long long' to 'id' is disallowed with ARC
  （同一模式重复 4 组）

根因：
  ① [_cmd isEqual:NSSelectorFromString(...)]
     SEL 不是 Objective-C 对象，对它发消息非法 —— 应用 sel_isEqual()。
     同时把它改成 dispatch_once 静态注册，避免热路径反复构造选择子。
  ② ProbeRecycledCall 返回 id，而返回值来自 BOOL 方法，写了
     (id)(long long)... 强转 —— ARC 下禁止整数与对象指针互转。
     被挂的四个方法返回 BOOL 或 void，不是对象指针；
     intptr_t 与 BOOL 在 arm64 上同在 x0 返回，ABI 一致，改用它。
     路由器返回类型随之从 id 改为 intptr_t（前置声明一并改）。

新增本地静态闸门（_recon/check_objc.py 第 6 组规则），把这两类
「只有 CI 才会暴露」的写法在本地先抓掉：
  6a 对 SEL 发消息
  6b ARC 下整数转 id
  6c 路由器返回类型必须是整数型

另外：本轮把并发分段引擎的**同构参考实现 + 本地验证台**写好并跑通
（_recon/segment_fetcher_ref.py）。它是纯 Python + 限速 Range 服务器，
在 Windows 上就能定量验证引擎语义，不需要 Mac：
  测试1 乱序到达/40 段按序交付、逐段逐字节正确      ✔
  测试2 并发提速：并发1 16.80s / 并发8 2.10s
        实测 8.02×，理论 8.00×（单连接限速 256KB/s）  ✔
  测试3 坏 host 自动重试并降级到备用 host，6/6 完整交付  ✔
  测试4 全部 host 失效时显式报错且不交付任何残片        ✔
这为阶段 3「并发分段」提供了可复用的算法基线：ObjC 版将按同一状态机
（段表驱动 / 固定并发 / 乱序入槽 / 严格按段号交付 / 失败重试与换 host）
实现，届时只需验证实现与基线的行为一致。
