fix(probe): 修「安装后一启动就闪退」—— performSelector 把整数返回值当对象

崩溃日志（bili-universal-2026-09-21-033533.ips）直接指出了位置：
  EXC_BAD_ACCESS (SIGSEGV) at 0x00000000ffffffff
  frame 0: objc_retain
  frame 1: +[BiliProbe bootstrap]
  frame 2: BiliProbeInit            ← dylib 的 constructor

根因：
  exit 前我加了这段探测 P2P 本地服务端口的代码 ——
      id r = [p2pMgr performSelector:NSSelectorFromString(@"getHttpServerPort")];
      port = [r integerValue];
  performSelector 声明返回 id，而 getHttpServerPort 实际返回**整数端口**。
  把整数当对象指针交给 ARC 去 retain（objc_retain）→ 读 0xffffffff → 段错误。
  0xffffffff 正是崩溃地址里的值。

教训（已写进代码注释）：
  **对签名未知的方法，绝不用 performSelector 取其返回值。**
  本类只有方法名（来自运行时 dump），没有 type encoding，
  因此只能判断 respondsToSelector，不能取值。

同时撤掉三个「签名靠推测」的 hook（IJKDashStreamItem.initWithStreamId:…、
IJKMediaPlayerItem.parseDash:videoId:audioId:、IJKMediaPlayerWrapper.prepareWithItem:）：
  class_replaceMethod 的 types 只是元数据、**不校验实现**，
  若真实签名与推测不同（如某参数实为对象而非 int），C 函数会错误读参并对
  垃圾指针 objc_retain → 同样是一启动就闪退。
  这些类在 t=0 就被 hook，风险不可接受。
  改为**只做类存在性探测**，不替换任何方法。

落点不受影响：静态分析已确定 IJKDashStreamItem.baseUrl / backupUrl0/1 是
CDN URL 所在字段；实现阶段会先取到真实 type encoding（真机打印一次
method_getTypeEncoding，或修正二进制 method list 解析）再挂 hook。

清理：删除随之失效的 3 个观测函数、6 个计数与其在 verdict/心跳中的引用，
避免 -Wunused-function 与死代码。
