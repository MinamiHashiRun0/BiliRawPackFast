fix(cdn): 修 unused variable 构建失败 + 补 SIDX 夹具生成与真实 IPA 端到端注入演练

1) 构建失败修复
   BSSegmentFetcher.m:154 error: unused variable 'r' [-Werror,-Wunused-variable]
   成因：requestURLForSegment: 里取了一次段范围却没用上（URL 只由 baseURL 的
   路径/查询串 + host 决定，段信息只影响 Range 头）。删掉即可。
   该类错误本地无法发现（Windows 上没有 clang 的 ObjC 前端），只能靠 CI。

2) 真实 IPA 端到端注入演练（_recon/test_inject_real_ipa.py）
   此前 inject_dylib.py 只在「合成 Mach-O」与「真实二进制的内存副本」上验证过，
   没跑过完整的 IPA 读写往返；workflow 的 --ipa 分支也从未真正执行。
   现在补上，并用真实 IPA（277MB）实测：
     zip 条目集合一致 ✓ (2825 个)
     主二进制长度不变 ✓ (630,083,392 字节)
     ncmds 145 → 146，sizeofcmds 16,096 → 16,168 (+72) ✓
     LC_LOAD_DYLIB 已加入 ✓ 共 98 条
     LC_CODE_SIGNATURE dataoff 614,459,904 → 614,459,976 (+72) ✓
     逐字节差异 52 处，**落在允许区外 0 处** ✓
   即注入对真实 IPA 的影响面严格限定为「header 计数 / 新命令 / 签名 dataoff」。
   注：本脚本第一版把 dataoff 字段位置写成命令起始+8，误报 1 字节越界；
      实测该字段在命令起始+16。修正后归零 —— 核对脚本自己也要用实测偏移。

3) SIDX 测试夹具（_recon/gen_sidx_fixtures.py + _recon/sidx_fixtures/）
   先查了 IPA 内是否有真实 m4s 可当夹具：只有 21 个内置音频/视频小文件，
   **均不含 sidx**（B站视频是运行时下载的）。因此没有真实样本可用，
   如实记录，不伪造。
   改为按 ISO/IEC 14496-12 构造 9 个夹具，并用独立 Python 解析器复核：
     v0_all_direct / v1_64bit_offsets / mixed_hier_and_empty  → 应成功
     hier_only / unknown_version / timescale_zero /
     truncated_table / no_sidx / zero_refs                    → 应失败
   其中 mixed_hier_and_empty 专门覆盖「层级引用与空段必须跳过而非当段用」。
   生成过程中两次算错 reference_count 偏移（先漏 box header 8B，再漏 reserved 2B），
   都被夹具自身的断言当场抓住 —— 夹具自身可验证是这次的关键。
   用途：将来在 macOS 上对拍 BSSidxIndex.m；CI 侧另行用纯 C 核心 + clang 跑。
