feat(probe): 从本地类转储定位播放链路落点 —— 不再靠真机反复试

用户的批评是对的：我手里一直有 classes.txt（3999 个类的完整方法表）和二进制字符串，
却让用户反复跑真机测试。本轮改为纯静态挖掘，一次把落点找全。

挖掘结果（IKJ = B站自研 FFmpeg 播放器内核，非 AVPlayer）：

  IJKFFMoviePlayerController          FFmpeg 内核直读；只有
                                      initWithContentURL:withOptions:
                                      **没有** initWithContentURL: —— 证实不经 AVPlayer
  IJKMediaPlayerWrapper               - prepareWithItem: / switchItem:   ← 喂给内核
  IJKMediaPlayerItem                  - parseDash:videoId:audioId:      ← 解析 playurl
                                      - getResolverData:video:audio:    ← 取解析结果
                                      - getBestStreams: / addMediaAssetStream:
                                      - hookUrl                         ← App 自带同名方法
  IJKDashStreamItem                   - initWithStreamId:bandwidth:baseUrl:fileSize:
                                        streamType:codecType:
                                      - baseUrl / backupUrl0 / backupUrl1  ← CDN URL 字段
  IJKDashStreamBridge                 - initWithMediaType:codecId:qn:bandwidth:
                                        url:backupUrls:                 ← url + 备用URL 入口
  IJKP2PManager                       + getHttpServerPort               ← P2P 起**本地 HTTP 服务**
                                      - openSocket:isLive:
  IJKP2PGRPCClient                    P2P 走 gRPC

由此解释全部真机现象：
  1. 视频字节由 FFmpeg 内核通过**原生 C++ I/O / P2P 原生栈**读取，
     不经 NSURLSession / NSURLRequest / NSURLProtocol
  2. P2P 在本地起 HTTP 服务（getHttpServerPort），播放器读 127.0.0.1:<port>
     —— 而我的媒体过滤器只匹配 bilivideo/mcdn/akamai/hdslb/upos，
     把 127.0.0.1 过滤掉了，所以即使有请求也不会记录
  3. AVAssetResourceLoader 自始至终未被使用（FFmpeg 路径不需要它）

新增观测点（全部来自上面的真实方法表，非猜测）：
  * IJKMediaPlayerItem  - parseDash:videoId:audioId:      记录解析到的流数量
  * IJKMediaPlayerItem  - getResolverData:video:audio:
  * IJKDashStreamItem   - initWithStreamId:bandwidth:baseUrl:fileSize:...
                        记 baseUrl / backupUrl 的 host（★ 这就是 CDN 重定向的落点）
  * IJKMediaPlayerWrapper - prepareWithItem:
  * 放宽媒体过滤器：加入 127.0.0.1 / localhost，用于验证 P2P 本地服务假设

这次不需要用户再试错 —— 落点已在静态层面确定。
