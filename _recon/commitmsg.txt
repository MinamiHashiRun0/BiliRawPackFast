fix(ci): 修 workflow YAML 解析失败 + 改用原始 entitlements

问题：GitHub 把 workflow name 显示成文件路径、workflow_dispatch 未注册、
push 触发的 run 0 秒即失败 —— 说明 workflow 根本没编译成功。

根因（本地用 PyYAML 定位到行号）：
  块标量 run: | 里嵌的 bash heredoc，正文被写在第 0 列，
  直接终止了 YAML 块标量；而结束标记 EOF 却是缩进的，两头都不对。
  第一次在 dist/README.txt（第 103 行），第二次在 ent.plist（第 166 行）。

修复：
  * README 输出改写为花括号分组 + 逐行 echo，不再用 heredoc
  * entitlements 不再硬编码最小集合，改为
    `codesign -d --entitlements :- <主二进制>` 从原 App Store 签名里抽原始值，
    抽不到才回退最小集合。比硬编码更正确：能保留 B站原本申请的权限。

附带：
  * 显式写 "on":（避免 YAML 把 on 解析成布尔 true 的歧义）
  * 新增 _recon/validate_workflow.py 作为推送前本地校验闸门
    （检查 secrets 出现在 if、空 run、heredoc 平衡、artifact 静默失败）
  * push 触发时忽略 _recon/**，避免侦察脚本改动就触发 macOS 构建

验证：本地 PyYAML 解析通过，11 个步骤全部识别，无 secrets-in-if、
无未闭合 heredoc、所有 upload-artifact 均设 if-no-files-found=error。
